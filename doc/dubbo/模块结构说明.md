# 模块结构说明

## 项目整体结构

```
mycat-demo (父模块)
├── provider (服务提供方父模块)
│   ├── facade (接口定义模块)
│   ├── common (公共模块)
│   ├── dao (数据访问层模块)
│   ├── integration (集成模块)
│   ├── web (Web 层模块)
│   └── service (服务实现模块，启动类)
└── consumer (服务消费方父模块)
    ├── facade (Consumer 内部接口定义)
    ├── common (公共模块)
    ├── dao (数据访问层模块)
    ├── integration (集成模块)
    ├── web (Web 层模块)
    └── service (服务模块，启动类)
```

## Provider 模块说明

### 1. provider-facade
- **作用**: 定义 Dubbo 服务接口和 DTO
- **依赖**: 无（纯接口定义）
- **内容**: 
  - Dubbo 服务接口（如 `UserService`）
  - 数据传输对象（如 `UserDTO`）
- **使用**: 供 Provider 和 Consumer 共同使用

### 2. provider-common
- **作用**: 公共工具类、常量、异常等
- **依赖**: Lombok
- **内容**:
  - 常量类（`CommonConstants`）
  - 工具类（`ResultUtil`）
  - 异常类
  - 枚举类

### 3. provider-dao
- **作用**: 数据访问层
- **依赖**: 
  - provider-common
  - MyBatis
  - Mapper
  - MySQL 驱动
- **内容**:
  - Entity 实体类
  - Mapper 接口
  - Mapper XML 文件

### 4. provider-integration
- **作用**: 第三方服务集成
- **依赖**: 
  - provider-common
  - Spring Boot Web（HTTP 客户端）
- **内容**:
  - 外部 API 客户端
  - 第三方服务调用封装
  - 消息队列集成等

### 5. provider-web
- **作用**: Web 层（Controller、DTO、VO）
- **依赖**: 
  - provider-common
  - Spring Boot Web
- **内容**:
  - Controller（可选，如果 Provider 也提供 HTTP 接口）
  - Request DTO
  - Response VO
  - 响应封装类

### 6. provider-service
- **作用**: 服务实现和启动类
- **依赖**: 
  - provider-facade
  - provider-common
  - provider-dao
  - provider-integration
  - provider-web
  - Dubbo
  - MyBatis
  - 数据库相关
- **内容**:
  - Dubbo 服务实现类（`@DubboService`）
  - 业务逻辑
  - 启动类（`ProviderApplication`）
  - 配置文件

## Consumer 模块说明

### 1. consumer-facade
- **作用**: Consumer 内部接口定义
- **依赖**: 
  - provider-facade（Dubbo 服务接口）
- **内容**:
  - Consumer 内部服务接口
  - Consumer 内部 DTO

### 2. consumer-common
- **作用**: Consumer 公共模块
- **依赖**: Lombok
- **内容**:
  - 常量类
  - 工具类
  - 异常类

### 3. consumer-dao
- **作用**: Consumer 数据访问层
- **依赖**: 
  - consumer-common
  - MyBatis
  - Mapper
  - MySQL 驱动
- **内容**:
  - Entity 实体类
  - Mapper 接口
  - Mapper XML 文件

### 4. consumer-integration
- **作用**: Consumer 第三方服务集成
- **依赖**: 
  - consumer-common
  - Spring Boot Web
- **内容**:
  - 第三方服务客户端
  - 外部 API 调用

### 5. consumer-web
- **作用**: Consumer Web 层
- **依赖**: 
  - consumer-common
  - Spring Boot Web
- **内容**:
  - Controller
  - Request DTO
  - Response VO
  - 响应封装类

### 6. consumer-service
- **作用**: Consumer 服务模块和启动类
- **依赖**: 
  - consumer-facade
  - consumer-common
  - consumer-dao
  - consumer-integration
  - consumer-web
  - provider-facade（Dubbo 服务接口）
  - Dubbo
- **内容**:
  - Controller（使用 `@DubboReference` 调用远程服务）
  - 业务逻辑
  - 启动类（`ConsumerApplication`）
  - 配置文件

```
  ├── consumer-facade

  ├── consumer-dao
  │   └── consumer-common
  ├── consumer-integration
  │   └── consumer-common
  ├── consumer-web

```

## 模块职责划分

| 模块 | 职责 | 是否可独立使用 |
|------|------|----------------|
| facade | 接口定义 | ✅ 是 |
| common | 公共代码 | ✅ 是 |
| dao | 数据访问 | ❌ 否，依赖 common |
| integration | 第三方集成 | ❌ 否，依赖 common |
| web | Web 层 | ❌ 否，依赖 common |
| service | 业务实现和启动 | ❌ 否，依赖所有模块 |

## 版本管理

所有子模块的版本都在父 POM 的 `dependencyManagement` 中统一管理，子模块引用时无需指定版本号：

```xml
<dependency>
    <groupId>org.lix</groupId>
    <artifactId>provider-facade</artifactId>
    <!-- 无需指定 version，自动使用父 POM 中的版本 -->
</dependency>
```

## 开发建议

1. **接口定义**: 所有 Dubbo 服务接口定义在 `provider-facade` 中
2. **公共代码**: 工具类、常量等放在 `common` 模块
3. **数据访问**: Entity 和 Mapper 放在 `dao` 模块
4. **第三方集成**: 外部服务调用放在 `integration` 模块
5. **Web 层**: Controller、DTO、VO 放在 `web` 模块
6. **业务逻辑**: 服务实现放在 `service` 模块
